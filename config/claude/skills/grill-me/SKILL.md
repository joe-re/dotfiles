# Grill Me

計画や設計について、ユーザーと合意に達するまで徹底的に質問し続けるスキル。曖昧なまま実装に進まず、決定事項の依存関係を順序立てて解消することが目的。

## 進め方

1. **対象の計画を把握する**
   直前の会話やユーザーの指示から、すり合わせ対象の計画・設計を特定する。不明な場合はユーザーに何について認識合わせをしたいか確認する。

2. **決定木を洗い出す**
   計画を構成する決定事項を洗い出し、依存関係を整理する。ある決定が別の決定の前提になっている場合は、前提となる決定から先に扱う。枝分かれがある場合はその先まで一つひとつたどる。

3. **質問は一度に一つだけ**
   複数の論点を一度にまとめて聞かない。今解決すべき最も上流の決定事項から、一問ずつ投げかける。

4. **各質問には推奨回答を添える**
   質問するときは、自分なりの推奨案とその理由を必ず併記する。ユーザーが即座に「それでいい」と即断できるようにする。AskUserQuestionツールを使う場合は、推奨案を選択肢の先頭に置き "(推奨)" を付す。

5. **コードベースで答えが分かるなら質問しない**
   その質問がコードベースの調査（既存実装、設定、ドキュメント等の確認）で答えられる場合は、ユーザーに聞く代わりに自分で調べて確認する。調査した内容と結論は簡潔に共有し、必要なら「この理解で合っているか」だけを確認する。

6. **回答を踏まえて次の分岐へ進む**
   ユーザーの回答（または調査結果）を受けて計画を更新し、次に解決すべき決定事項に進む。これを決定木の末端まで繰り返す。

7. **完了条件**
   すべての決定事項について合意が得られたら、最終的な計画をまとめてユーザーに提示する。実装やコード変更が必要な場合は、ここで初めて着手する。

## 注意点

- 一度に複数の質問を並べない。
- 質問のための質問をしない。調査で解決できることは調査する。
- 推奨案は「なんとなく」ではなく、コードベースや制約から導かれる具体的な根拠を持たせる。
- ユーザーが回答を保留・変更した場合は、その決定に依存する下流の決定事項も見直す。
